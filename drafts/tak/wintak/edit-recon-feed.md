# Edit RECON feed

META: slides

As a command post you create and maintain the unit's RECON feed: create it, get the other CP users subscribed, then process incoming observations and send the processed markers back to the feed.

## Find the Data Sync tools

![Home tab — Data Sync tools](_assets/Kuva39.png)

In WinTAK's toolbar, the **Home tab** holds the Data Sync tools.

## Create a new feed

![New Feed](_assets/Kuva40.png)

Operating as a command post, you create the feeds. Press **New Feed**.

At the command post, _one_ user creates the feeds; the other CP users and the rest of the unit subscribe to them.

## Name the feed

![Feed details](_assets/Kuva41.png)

Create the feed with:

- **Name**: Recon
- **Group**: tak_default
- **Default Role**: Read Only

Change the default group to **tak_default** and the default role to **Read Only**.

## Feed created

![Feed appears subscribed](_assets/Kuva42.png)

The feed is created and immediately shows as subscribed in the **Data Sync** menu for its creator. Other command-post users now subscribe to it (typically the **RECON** feed).

## Subscribe: download and stay synced

![Download and stay synced](_assets/Kuva43.png)

In the feed's view, other CP users select **Download and stay synced**. The feed then appears in their **Data Sync** menu.

## Receive notifications

![Incoming notifications](_assets/Kuva45.png)

WinTAK shows notifications like these when new observations arrive.

## Open the Notifications view

![Yellow flag → Notifications](_assets/Kuva47.png)

Press the **yellow flag** symbol to open the **Notifications** view. It lists received notifications — process each one as below, then send it to the RECON feed.

## Open an observation

![Open the observation](_assets/Kuva48.png)

Observations are opened and processed from the map. Open the observation you want to process.

## Open Marker Details

![Marker Details icon](_assets/Kuva49.png)

From the circle menu, select the **Marker Details** icon (to the right of the trash can). The **Marker Details** view opens.

## Record your conclusion

When recording interpretations, keep your conclusion separate from the original description — use the notation _HQ CONCLUSION: (your assessment)_.

Consider OPSEC: do not put operational enemy information here — use cover terms.

## Change the affiliation

![Change Affiliation](_assets/Kuva50.png)

In Marker Details, change the observation type (unknown, friend, own, neutral) to match your conclusion by pressing **Change Affiliation**.

## Pick the new type

After **Change Affiliation**, the **Type menu** opens — set the marker according to your conclusion. The marker then updates.

## Mark it as processed

![Underscore in front of the title](_assets/Kuva55.png)

Add a notation to the marker's title — an **underscore in front** — to show the command post has processed it.

## Decide on immediate reporting

Determine whether the observation is an _immediately reportable matter_.

IMPORTANT: if it is, send a report using the prescribed messaging tools to the prescribed recipients — don't rely on the feed alone.

## Send the marker to the feed

![Send in Marker Details](_assets/Kuva56.png)

So the whole force sees the processed marker, press **Send** in the Marker Details menu.

## Include attachments

![Include Attachments — Yes](_assets/Kuva57.png)

Choose **Yes** to the _Include Attachments_ question.

## Choose the RECON feed

![Send To menu](_assets/Kuva58.png)

The **Send To** menu opens on the right — send the marker to the **RECON** feed. Work through every processed observation the same way.
